# Decisions

- User authenication is out of scope as trade off for time and complexity.
- Skip deteministic Playwright integration test half way implementation due to time constraints. Spend the time on more useful Property based test and E2E agentic test plan, verification and auto-fix instead that can catch more integration issues and fix it quickly.
- Every page renders dynamically, with no static shell or Partial Prerendering, as the trade-off for a strict nonce-based CSP: Next's prerendered shell carries no nonce, so its scripts would be blocked and the page would never hydrate. With one read-only page and small data the extra render cost is negligible, and the rate limiter covers the load risk. See [ADR 0003](../docs/adr/0003-read-only-db-and-security-headers.md).
- Intentionally did not build any write path: no editing of listings or agencies and no runtime migrations. SQLite is opened read-only at runtime and only `db:migrate` and `db:seed` write to it, so a compromised request cannot change data. The cost is that data only changes on re-seed and the as-of time is fixed. See [ADR 0003](../docs/adr/0003-read-only-db-and-security-headers.md).
- Rate limiting is in-process memory (`RateLimiterMemory`) rather than a shared store such as Redis. It ships and is tested with the app with no extra infrastructure, at the cost that each instance counts on its own and a restart clears the counts. Move to the shared store behind the same interface before running more than one instance. See [ADR 0004](../docs/adr/0004-in-app-rate-limiting.md).
- Component styles live in sibling CSS modules with semantic class names (`.tile`, `.value`), built from Tailwind token utilities with `@apply`, rather than long Tailwind `className` strings. Repeated layout became shared React components and one shared module (`CardRow`, `analytics-layout.module.css`) instead of being copied into the page, components and loading skeleton. The trade-off is two files per component and a custom Turbopack loader rule, in exchange for readable markup, one home per piece of layout knowledge, and no `cn()` merges to override shadcn defaults. ESLint enforces it. See [ADR 0005](../docs/adr/0005-css-modules-for-component-styles.md).
