# Product Intent: Rental Analytics v1

Requirements and acceptance criteria for the first release of the Rayblue Agency Group dashboard. This file is the single home for **what v1 must do** and **how we know it does it**. Terms are defined in the [README glossary](README.md#domain-glossary); how it is built is in [ENGINEERING.md](ENGINEERING.md); how it looks is in [DESIGN.md](DESIGN.md).

Status: draft · Last updated 24 Oct 2026 (seed scope and property-manager names amended for the prototype)

## 1. Intent

Rayblue Agency Group runs individual agencies in every Australian state and territory. The group manager has no single place to see how rental activity is trending across the group. v1 gives them one page, **Rental analytics**, that shows how many new rental listings the group, a state or a single agency has added per day, week and month.

**Success:** from one screen and at most two filter changes, the group manager can answer:

1. How many new rental listings did we add today, this week and this month, and how does that compare with the last period?
2. Which states drive that volume?
3. Which agencies lead, and are they growing or shrinking?

Real estate is a regulated industry and the app is public (no sign-in). Reliability, security and correctness of the figures carry the same weight as the features.

## 2. Users

| User | Needs |
| --- | --- |
| **Group manager** (primary) | The three answers above, for the whole group or narrowed to a state or agency. |
| **Public viewer** (secondary) | Anyone with the URL can open the app. They must see only sample, aggregate data and nothing that identifies a person or a property. |

## 3. Scope

### In scope (v1)

- **App shell:** a left drawer sidebar with one item, **Rental analytics**.
- **Rental analytics page:**
  - Filters: state or territory, agency, and listing period (Daily, Weekly, Monthly), all held in the URL.
  - KPI tiles: new listings today, this week, this month, and number of agencies.
  - Trend chart: new listings per day, week or month.
  - By-state bars: new listings per state or territory.
  - Top agencies table: leading agencies by new listings, with share and change.
- Light and dark themes, following the operating system setting.
- Synthetic data seeded into SQLite.

### Out of scope (v1)

- Sign-in, accounts and roles
- Creating or editing listings or agencies
- Live integrations with listing portals or agency systems
- Metrics beyond listing counts (vacancy, rent prices, days on market)
- Listing-level detail of any kind (addresses, rents, photos, people)

## 4. Assumptions and constraints

- **Public and read-only.** There is no sign-in, so every page and endpoint is treated as public.
- **Sample data only.** All data is synthetic and generated by `npm run db:seed`. No real customer, tenant, landlord or staff data is loaded in v1.
- **Time.** Timestamps are stored in UTC and bucketed in `Australia/Sydney`. Weeks start on Monday.
- **As-of time.** Every dataset records the time it was last refreshed (its *as-of time*). "Today", "this week" and "this month" are relative to the as-of time, not the server clock. This is the injected "now" from [ENGINEERING.md › Practices](ENGINEERING.md#4-practices).
- **Hosting-agnostic.** Requirements describe outcomes; they do not assume a hosting platform.

## 5. Functional requirements

Each acceptance criterion (AC) has a stable ID, a Given / When / Then statement and how it is verified: `unit`, `property`, `component`, `integration`, `CI` or `manual` (see [ENGINEERING.md › Testing strategy](ENGINEERING.md#5-testing-strategy)).

### F1. App shell and navigation

- **AC-NAV-1** — *Given* any page, *when* it loads, *then* a left sidebar shows "Rayblue Agency Group", the context line for the current scope, and exactly one navigation item, "Rental analytics". `component`
- **AC-NAV-2** — *Given* the Rental analytics page is open, *then* its navigation item is visually marked current and has `aria-current="page"`. `component`
- **AC-NAV-3** — *Given* a visitor opens `/`, *then* they are redirected to `/rental-analytics`. `integration`
- **AC-NAV-4** — *Given* a viewport narrower than about 808px, *when* the page loads, *then* the sidebar is hidden behind a labelled menu button that opens it as a sheet, and the sheet closes with Escape or after choosing an item. `component`
- **AC-NAV-5** — *Given* a keyboard-only user, *then* every sidebar control is reachable with Tab and shows a visible focus ring. `component` + `manual`
- **AC-NAV-6** — *Given* there is no sign-in, *then* the sidebar footer shows "Group manager view" and never claims a signed-in user. `component`

### F2. Filters and URL state

Search params: `state`, `agencyId`, `granularity` (names from [ENGINEERING.md › Request flow](ENGINEERING.md#request-flow-rental-analytics)).

- **AC-FLT-1** — *Given* no search params, *when* the page loads, *then* it shows all states and territories, all agencies, and the Daily period. `component`
- **AC-FLT-2** — *Given* the "State or territory" select, *then* it offers "All states and territories" followed by the eight states and territories by full name (New South Wales, Victoria, Queensland, Western Australia, South Australia, Tasmania, Australian Capital Territory, Northern Territory). `component`
- **AC-FLT-3** — *Given* the "Agency" select, *then* it offers "All agencies" followed by the agencies in the selected state (or every agency when no state is selected), sorted by name, each showing its state. Typing jumps to matching agencies. `component`
- **AC-FLT-4** — *Given* the "Listing period" tabs, *then* they offer Daily, Weekly and Monthly, wired as `role="tab"` with arrow-key navigation. `component`
- **AC-FLT-5** — *Given* any filter or tab change, *then* the URL search params update, the page shows the new view, and no other client-side state holds the selection. `component`
- **AC-FLT-6** — *Given* a visitor changes filters several times, *when* they press Back or Forward, *then* each earlier view is restored exactly. `manual`
- **AC-FLT-7** — *Given* a URL copied from any view, *when* someone else opens it, *then* they see the same filters and the same figures (for the same as-of time). `integration`
- **AC-FLT-8** — *Given* an unknown or malformed value for any param (for example `state=XYZ`, `granularity=hourly`, `agencyId=abc`, or a 10,000-character string), *when* the page loads, *then* that param falls back to its default, the response is HTTP 200, and no error text or input echo appears. `unit` + `integration`
- **AC-FLT-9** — *Given* a URL whose `agencyId` is not in the selected `state`, *when* the page loads, *then* the agency filter is dropped and the state filter kept. `unit`
- **AC-FLT-10** — *Given* an agency is selected, *when* the user changes the state to one that does not contain that agency, *then* the agency resets to "All agencies". `component`

### F3. KPI tiles

Four tiles in a "Listing totals" section, styled per [DESIGN.md › KPI tile](DESIGN.md#kpi-tile).

| Tile | Value | Comparison note |
| --- | --- | --- |
| New listings today | Count for the as-of day, up to the as-of time | "To 9:00 am · last Saturday 241": the same weekday last week, full day |
| New listings this week | Count from Monday to the as-of time | "Week to date · last week 3,369": the previous full week |
| New listings this month | Count from the 1st to the as-of time | "Month to date · September 14,210": the previous full month, by name |
| Agencies | Number of agencies in the current scope | "Across 8 states and territories", or "In Victoria" when a state is selected |

- **AC-KPI-1** — *Given* any combination of filters, *then* the three listing tiles show counts for that scope only, and the Agencies tile shows the number of agencies in scope (1 when an agency is selected). `component` + `integration`
- **AC-KPI-2** — *Given* the current day, week or month is incomplete, *then* its note says "To <time>", "Week to date" or "Month to date", so a partial period is never presented as a full one. `component`
- **AC-KPI-3** — *Given* seeded data with known counts, *then* each tile value and comparison equals the expected count for its period, including across a DST change and a month end. `integration` + `property`
- **AC-KPI-4** — *Given* any value, *then* it is formatted with `en-AU` grouping (`3,369`) in tabular numerals, and is never coloured. `component`
- **AC-KPI-5** — *Given* the listing period tabs change, *then* the KPI tiles do not change (they always show today, this week and this month). `component`

### F4. Trend chart

| Period | Range | Bucket label | Tooltip label |
| --- | --- | --- | --- |
| Daily | Last 14 days | `24 Oct` | `Sat 24 Oct 2026` |
| Weekly | Last 12 weeks, starting Monday | `19 Oct` | `Week of 19 Oct 2026` |
| Monthly | Last 12 months | `Oct` | `October 2026` |

- **AC-TRD-1** — *Given* a period, *then* the chart shows exactly the range in the table above, ending with the bucket that contains the as-of time. `unit` + `component`
- **AC-TRD-2** — *Given* the last bucket is incomplete, *then* its tooltip label ends with "(to date)". `component`
- **AC-TRD-3** — *Given* a bucket with no listings, *then* it appears with a value of 0; buckets are never skipped. `property`
- **AC-TRD-4** — *Given* any filters, *then* the card title reads "New listings per day / week / month", the description states the range and scope, and the series is named for the scope ("All Rayblue agencies", the state name, or the agency name). `component`
- **AC-TRD-5** — *Given* a pointer hovers or a keyboard user focuses a point, *then* a tooltip shows the long date label and the tabular value, styled per [DESIGN.md › Charts](DESIGN.md#7-charts). `component` + `manual`
- **AC-TRD-6** — *Given* a screen reader, *then* the chart has `role="img"` and an `aria-label` that states scope, range, latest and peak values (for example "New listings per day for All states and territories, 11 Oct to 24 Oct. Latest 258, peak 621."), and the same figures are available as a table to assistive technology. `component`

### F5. By-state bars

- **AC-STA-1** — *Given* any period, *then* the "New listings by state" card shows all eight states and territories with group-wide totals over the trend chart's range, sorted from highest to lowest. `component` + `integration`
- **AC-STA-2** — *Given* each row, *then* it shows the state code, its number of agencies ("58 agencies", "1 agency"), a bar scaled to the highest value, and the tabular count. `component`
- **AC-STA-3** — *Given* a state is selected, or an agency in that state, *then* every bar stays visible and bars for other states fade to 35% opacity; the card description says which state is highlighted. `component`
- **AC-STA-4** — *Given* the eight state totals, *then* they sum to the group total for the same range. `property`

### F6. Top agencies table

Columns: Agency · State · New listings · Share of group (or "Share of NSW" when a state is selected) · vs previous.

- **AC-AGY-1** — *Given* any period, *then* the table lists the top 8 agencies in the current state scope by new listings over the trend chart's range, highest first. `component` + `integration`
- **AC-AGY-2** — *Given* each row, *then* Share is the agency's count divided by the scope total, shown to one decimal place with "%"; Share values across all agencies in scope sum to 100% (within rounding). `unit` + `property`
- **AC-AGY-3** — *Given* each row, *then* "vs previous" compares the agency's count with the previous range of equal length (previous 14 days, 12 weeks or 12 months), shown as "+4%", "−3%" (U+2212) or "0%"; when the previous count is 0 it shows "—". `unit`
- **AC-AGY-4** — *Given* an agency is selected, *then* its row is marked selected (`aria-selected`), and if it is outside the top 8 it is added as a ninth row. `component`
- **AC-AGY-5** — *Given* a sortable column header, *then* it is a button that sorts the visible rows and exposes `aria-sort`. `component`
- **AC-AGY-6** — *Given* no agencies match the scope, *then* the table shows an empty-state message instead of rows. `component`
- **AC-AGY-7** — *Given* a screen reader, *then* the table has a caption ("Top agencies by new listings") and numeric columns are right-aligned and tabular. `component`

### F7. Page header and data freshness

- **AC-HDR-1** — *Given* the page, *then* it has one `h1`, "Rental analytics", and a meta line "<scope> · Sample data · Updated <time>, <date>" (for example "All states and territories · Sample data · Updated 9:00 am, 24 Oct 2026"), with the as-of time in Sydney time. `component`
- **AC-HDR-2** — *Given* the server clock is more than 24 hours past the as-of time, *then* a warning alert says when the data was last updated and that figures may be out of date. `unit` + `component`
- **AC-HDR-3** — *Given* the same URL and the same dataset, *then* every figure on the page is identical on every request. `integration`

### F8. Loading, empty and error states

- **AC-STE-1** — *Given* data is loading, *then* each card shows a skeleton of its final size so the layout does not jump. `component`
- **AC-STE-2** — *Given* a scope with no listings in range, *then* tiles show 0, the chart shows a flat zero series, and nothing is shown as an error. `component`
- **AC-STE-3** — *Given* a server error while building the page, *then* an error view shows a plain message and a Retry button, and contains no stack trace, file path, SQL or environment value. `component` + `integration`
- **AC-STE-4** — *Given* an unknown route, *then* a not-found page shows with a link back to Rental analytics and HTTP 404. `integration`

### F9. Themes

- **AC-THM-1** — *Given* the operating system prefers dark, *then* the app renders with the dark token set from [DESIGN.md › Dark mode](DESIGN.md#9-dark-mode); otherwise light. The sidebar chrome is dark in both. `manual`

## 6. Data and counting rules

- A listing counts **once**, in the bucket that contains its `listedDate`, converted to `Australia/Sydney`.
- Filters narrow by the agency's state and by agency; they never change how a listing is bucketed.
- **Prototype seed scope:** the seed covers the **last 30 days** before the as-of time, for agencies in **NSW, VIC and QLD only**. Other states and territories have no agencies and no listings and still appear with 0 (AC-STA-1). Buckets and comparison periods older than 30 days are 0, so Weekly and Monthly trends and "vs previous" are mostly 0 or "—" by design.
- Listings carry a `status` (`active`, `leased`, `withdrawn`); every listing counts once on its `listedDate`, whatever its status.

- **AC-DAT-1** — The listing-count invariants in [ENGINEERING.md › Property-based tests](ENGINEERING.md#property-based-tests) hold for generated data: conservation, exclusivity, continuity (including DST changes and month and year ends), filter monotonicity, and daily-to-weekly consistency. `property`
- **AC-DAT-2** — *Given* a fixed seed value, *then* `npm run db:seed` produces the same dataset every time. `integration`
- **AC-DAT-3** — *Given* the seeded dataset, *then* NSW, VIC and QLD each have at least one agency, no other state has agencies, every agency has listings in the last 30 days, and no listing is after the as-of time. `integration`

## 7. Non-functional requirements

### 7.1 Security (public, read-only)

- **AC-SEC-1** — The app has no write paths: no server actions, no route handlers other than `GET`, and no form that submits to the server. `CI` + `manual` (code review)
- **AC-SEC-2** — All search params are parsed with a schema at the page boundary before use (AC-FLT-8). No param can widen a query beyond the fixed ranges in F4, so no request can trigger unbounded work. `unit`
- **AC-SEC-3** — The database is opened read-only at runtime. All queries go through Drizzle with bound parameters; no SQL is built by string concatenation. `integration` + `manual` (code review)
- **AC-SEC-4** — Every response sets: a Content Security Policy that allows scripts, styles, fonts and images from the app's own origin only (`object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`); `Strict-Transport-Security`; `X-Content-Type-Options: nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; and a `Permissions-Policy` that disables camera, microphone and geolocation. `X-Powered-By` is not sent. `integration`
- **AC-SEC-5** — Error responses and logs never include stack traces, file paths, SQL or environment values in what the client receives. `integration`
- **AC-SEC-6** — The repository contains no secrets; configuration comes from environment variables validated at start-up, with `.env.example` documenting each one. `CI` + `manual`
- **AC-SEC-7** — CI fails when `npm audit --omit=dev` reports a high or critical vulnerability. `CI`

### 7.2 Privacy and regulatory

The app is designed so that it handles no personal information. This is a design goal, not a compliance claim; loading real data needs the review in §9.

- **AC-PRV-1** — Services return aggregates only: counts plus agency and state names and ids. Listing addresses and rents never leave `src/data`. `CI` (typecheck of service return types)
- **AC-PRV-2** — *Given* the seeded dataset, *when* any page or endpoint is requested, *then* the response contains no seeded listing address, weekly rent or property-manager name. `integration`
- **AC-PRV-3** — The seed generates no real names of people: property-manager names are fictitious and never leave `src/data`; agency names are fictitious ("Rayblue Parramatta"). `unit` + `integration` (AC-PRV-2)
- **AC-PRV-4** — "Sample data" is visible on every page (AC-HDR-1), so figures cannot be mistaken for real agency performance. `component`
- **AC-PRV-5** — The app sets no cookies, loads no third-party scripts, trackers or analytics, and makes no runtime requests to other hosts; fonts are self-hosted. `integration` + `manual` (browser network panel)

### 7.3 Reliability and deployment

- **AC-REL-1** — Every pull request runs `npm run lint`, `npm run typecheck`, `npm test` and a production build in CI. `main` is protected: merging needs a passing CI run and an approving review. `CI` + `manual` (repository settings)
- **AC-REL-2** — Builds are reproducible: `npm ci` from the committed lockfile, Node.js 24 pinned in `.nvmrc` and `package.json#engines`. `CI`
- **AC-REL-3** — The database the app reads is migrated and seeded during the build and shipped with the release; the running app never migrates or writes to it. `integration`
- **AC-REL-4** — `GET /api/health` returns HTTP 200 with `{ "status": "ok", "version": "<release>", "database": "ok" }` and `Cache-Control: no-store`, or HTTP 503 with `"database": "unavailable"` when the database cannot be read. It returns nothing else. `integration`
- **AC-REL-5** — *Given* a missing or invalid environment variable, or a database file that is missing or on a different migration than the code expects, *when* the server starts, *then* it exits with a non-zero code and one clear log line. `integration`
- **AC-REL-6** — Each release is an immutable, versioned build. `docs/runbook.md` documents how to deploy, how to roll back to the previous release in one step, how to check health after a deploy, and the host-level rate limiting and firewall the app relies on. `manual`
- **AC-REL-7** — Server logs are structured (one JSON object per line with time, level, route, status and duration) and contain no request bodies, cookies or personal data. `integration`

### 7.4 Performance

Measured on the production build with the seed dataset; results recorded with the release.

- **AC-PRF-1** — `/rental-analytics` responds in 500 ms or less at the 95th percentile on a developer machine. `manual`
- **AC-PRF-2** — Lighthouse (desktop) performance score is 90 or higher. `manual`
- **AC-PRF-3** — After a filter or period change, the updated view is visible within 1 second. `manual`

### 7.5 Accessibility

- **AC-A11Y-1** — The page meets WCAG 2.1 AA, following [DESIGN.md › Accessibility](DESIGN.md#8-accessibility). Lighthouse accessibility scores 100 with no axe violations. `manual`
- **AC-A11Y-2** — Every control is operable by keyboard alone with a visible focus ring; components are tested by role and label. `component`
- **AC-A11Y-3** — The document uses `<html lang="en-AU">`, landmarks (`nav`, `main`, labelled sections) and one `h1`. `component`
- **AC-A11Y-4** — With `prefers-reduced-motion`, transitions are removed. `manual`

### 7.6 Compatibility and layout

- **AC-CMP-1** — The app works in the latest two versions of Chrome, Edge, Firefox and Safari, on desktop and mobile. `manual`
- **AC-CMP-2** — From 360px wide upwards there is no horizontal page scroll; the agencies table scrolls inside its own frame. `manual`

### 7.7 Maintainability

- **AC-MNT-1** — The layering and import rules in [AGENTS.md](AGENTS.md) hold; nothing imports upward. `CI` (lint)
- **AC-MNT-2** — `npm run lint && npm run typecheck && npm test` passes on `main`. `CI`
- **AC-MNT-3** — `src/utils` and `src/services` have full test coverage. `CI`

## 8. Definition of done (v1 release)

- [ ] Every AC above passes by its stated method.
- [ ] CI is green on `main`, including the production build and dependency audit.
- [ ] `docs/runbook.md` is written and a rollback has been rehearsed once.
- [ ] Performance and accessibility results (AC-PRF, AC-A11Y-1) are recorded with the release.
- [ ] README, ENGINEERING and DESIGN agree with this file.

## 9. Open questions and later work

- **Sign-in and roles** before any real data is shown, so data can be limited by state or agency.
- **Privacy impact assessment** before loading real listing data, covering the Privacy Act 1988 and state real estate record-keeping rules.
- **Log retention** period once a hosting platform is chosen.
